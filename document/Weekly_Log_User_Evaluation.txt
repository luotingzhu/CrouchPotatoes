零、方法说明 / 0. Method Note
================================================================================

  本记录采用「角色化走查」（persona-based walkthrough）：
  This log uses a persona-based walkthrough:

    - 按产品的真实使用场景定义 10 个用户画像（角色、设备、目标各不相同）。
      Ten personas are defined from real usage scenarios, differing in role,
      device and goal.
    - 每个画像独立完成指定任务，记录卡点、误判与放弃点。
      Each persona completes the assigned tasks independently; friction,
      misinterpretation and abandonment points are recorded.
    - 评价维度固定为四项，1–5 分，便于横向比较。
      Four fixed dimensions, scored 1–5, for comparability.

  评分口径 / Scoring rubric:
    1 分 = 无法完成或强烈抵触 / blocked or strongly resistant
    3 分 = 能完成但需要试错 / completed with trial and error
    5 分 = 顺畅且愿意再用 / smooth and willing to return

  四项维度 / Four dimensions:
    上手成本 Onboarding   能否在不求助的情况下开始
                          Can they start unaided
    任务完成 Task         能否完成核心任务（抓取 → 报告 → 追问）
                          Can they complete the core loop
    信任感 Trust          是否相信输出可用于工作判断
                          Do they trust the output for work decisions
    复用意愿 Retention    下次是否还会打开
                          Would they open it again

  说明 / Note:
    本记录用于在真实用户测试前系统性地定位问题；真实用户的访谈与评分
    需按第 5 节的脚本另行采集并替换本表分数。
    This log systematically locates problems before real-user sessions; actual
    interviews and scores must be collected with the script in section 5 and
    substituted into the tables.

四、建议总结 / 4. Recommendations
================================================================================

P0 · 必须在 Checkpoint 3 之前完成 / Must ship before Checkpoint 3
--------------------------------------------------------------------------------
  1. 主应用响应式适配
     Responsive layout for the main app
     建议 / How:
       ≤900px 时侧栏折叠为抽屉，内容区单列；表格改为纵向卡片；
       底部事件条默认隐藏。介绍页已有断点，可复用同一套变量。
       Below 900px collapse the sidebar into a drawer, switch to a single
       column, turn tables into stacked cards and hide the live strip by
       default. The landing page already has breakpoints to reuse.
     理由 / Why: 3/10 用户在此直接放弃，且二维码推广必然带来手机访问。
                 Three of ten abandoned here, and QR promotion guarantees
                 mobile traffic.

  2. 报告导出与分享
     Report export and sharing
     建议 / How:
       报告详情加「导出 PDF」与「复制分享链接」；先做浏览器打印样式，
       成本最低且足够演示。
       Add "Export PDF" and "Copy share link" to report detail; a print
       stylesheet is the cheapest credible version.
     理由 / Why: 4/10 用户明确提出；B2B 场景下报告的价值在于被转发。
                 Four of ten asked for it; in B2B the value of a report is
                 that it gets forwarded.

  3. 补齐政治与商业统计的真实数据源
     Real sources for Politics and Business Stats
     建议 / How:
       各接 1 个真实站点；在此之前，在界面上明确标注"示例数据"，
       而不是让用户自己发现。
       Connect one real site each; until then label these modules as sample
       data instead of letting users discover it.
     理由 / Why: 3/10 用户看到示例数据后开始怀疑全部数据。
                 Three of ten began doubting the entire dataset.

P1 · 本迭代内完成 / Within this iteration
--------------------------------------------------------------------------------
  4. 生成过程分阶段反馈
     Staged progress during generation
     建议 / How: 按"取数 → 摘要 → 经济分析 → 政策"四段显示进度与已用时，
                并把总耗时预期写在按钮旁。
     How: show four stages (select → summary → economic → policy) with
     elapsed time and an expectation next to the button.
     理由 / Why: 4/10 用户在等待中怀疑卡死，1 人因此刷新页面。

  5. 数据新鲜度前置
     Surface freshness before generating
     建议 / How: 报告页顶部显示各订阅模块的最新数据时间；过旧时在生成按钮
                上方先给提示，而不是生成后再告知。
     How: show the newest timestamp per subscribed module on the report page
     and warn above the button rather than after generation.
     理由 / Why: 2/10 用户在等待 30 秒后才知道数据是旧的。

  6. 原始数据支持筛选与搜索
     Filtering and search for raw data
     建议 / How: 按模块、数据源、时间范围筛选；标题关键词搜索走已有的
                全文索引，前端加一个输入框即可。
     How: filter by module, source and date range; title keyword search can
     use the existing full-text index with one input field.
     理由 / Why: 3/10 用户想看来源却只能看到最近 12 条。

  7. 首次登录引导
     First-run onboarding
     建议 / How: 空状态下给三步卡片「选模块 → 抓取数据 → 生成报告」，
                每完成一步打勾。
     How: an empty-state card with three steps (pick modules → fetch →
     generate), ticking off as each completes.
     理由 / Why: 2/10 新用户不知道操作顺序。

  8. 统一演示账号口径
     Align demo-account copy
     建议 / How: 介绍页直接写出 demo / demo1234，与登录页一致。
     How: state demo / demo1234 on the landing page, matching the login page.
     理由 / Why: 3/10 用户在两处看到不同说法，产生困惑；改动成本极低。

六、结论 / 6. Conclusion
================================================================================

  1. 核心链路成立：抓取 → 报告 → 追问三步都能走通，10 位画像中 8 位完成了
     核心任务，说明产品不是"两个割裂的演示"。
     The core loop holds: eight of ten personas completed fetch → report →
     follow-up, so the product is not two disconnected demos.
  2. 最大的短板是移动端与"带走能力"：手机无法正常使用，报告无法导出。
     The biggest gaps are mobile and portability: the app is unusable on a
     phone and reports cannot leave the system.
  3. 信任感受数据质量拖累：示例数据一旦被看见，会连带影响真实数据的可信度。
     Trust is dragged down by data quality: once sample data is spotted, it
     contaminates confidence in the real rows too.
  4. 复用意愿（2.7）低于任务完成（3.2），说明产品"能用"但还没有"必须用"的
     理由，下一步应强化定期报告与提醒。
     Retention (2.7) trails task completion (3.2): the product works but has
     no must-use reason yet; periodic reports and alerts are the next lever.
